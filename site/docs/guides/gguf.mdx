# Run GGUF models

For optimal performance and memory consumption, use prepared OpenVINO IR models from [OpenVINO on Hugging Face](https://huggingface.co/OpenVINO) whenever a suitable model is available. These models are created by exporting and compressing Hugging Face models with [Optimum Intel](https://huggingface.co/docs/optimum-intel/openvino/export). If no prepared IR is available, you can use the same export path to create one from the source model.

Use the GGUF frontend when your model is available only in GGUF format or you need to run an existing GGUF file directly.

OpenVINO GenAI can load a local `.gguf` file directly, including its tokenizer metadata. No Optimum export is required. `ENABLE_GGUF` is enabled by default in GenAI CMake. Use a compatible OpenVINO build that includes the GGUF frontend.

The default `GGUF_READER="LEGACY"` supports the `llama`, `qwen2`, and `qwen3` architectures. Select `GGUF_READER="FRONTEND"` explicitly to use the OpenVINO GGUF frontend, which supports more architectures and is expected to provide better model quality through more complete handling of GGUF metadata.

:::warning Preview feature
The GGUF frontend is in preview. Architecture, quantization, tokenizer, and attention-backend support depend on the OpenVINO version. Generated output can differ from other runtimes. If the default legacy reader fails, GenAI includes a suggestion to try the frontend in the error message; retry by selecting it explicitly.
:::

Prefer models quantized in `Q4_0` or `Q8_0` format for better performance and accuracy. Their quantization layouts are closest to those used by OpenVINO.

## Generate text

Replace `model.gguf` with the path to your downloaded model. For a base model without a chat template, set `apply_chat_template=False` in Python or `config.apply_chat_template = false` in C++.

<LanguageTabs>
    <TabItemPython>
        ```python
        import openvino_genai as genai

        pipe = genai.LLMPipeline("model.gguf", "CPU", GGUF_READER="FRONTEND")
        print(pipe.generate("Explain why the sky is blue.", max_new_tokens=64))
        ```
    </TabItemPython>
    <TabItemCpp>
        ```cpp
        #include <iostream>
        #include <openvino/genai/gguf.hpp>
        #include <openvino/genai/llm_pipeline.hpp>

        int main() {
            ov::genai::LLMPipeline pipe(
                "model.gguf", "CPU", ov::genai::gguf_reader("FRONTEND"));
            ov::genai::GenerationConfig config;
            config.max_new_tokens = 64;
            std::cout << pipe.generate("Explain why the sky is blue.", config);
        }
        ```
    </TabItemCpp>
</LanguageTabs>

## Use the tokenizer and stream a chat

The pipeline constructs its tokenizer from the frontend's model metadata. You can also construct `genai.GGUFTokenizer("model.gguf")` independently, without exporting tokenizer IR files. In C++, include `<openvino/genai/gguf.hpp>` and use `ov::genai::GGUFTokenizer`. The existing `Tokenizer("model.gguf")` path also remains supported.

```python
import openvino_genai as genai

pipe = genai.LLMPipeline("model.gguf", "CPU", GGUF_READER="FRONTEND")
tokenizer = pipe.get_tokenizer()
encoded = tokenizer.encode("Hello", add_special_tokens=False)
print(tokenizer.decode(encoded.input_ids))

history = genai.ChatHistory()
history.append({"role": "user", "content": "Explain gravity in one sentence."})
result = pipe.generate(
    history,
    max_new_tokens=64,
    streamer=lambda text: print(text, end="", flush=True),
)
history.append({"role": "assistant", "content": result.texts[0]})
history.append({"role": "user", "content": "Now give an example."})
print(pipe.generate(history, max_new_tokens=64))
```

Chat requires a suitable template in the GGUF metadata. See [Tokenization](./tokenization.mdx) for configuring the tokenizer and [Streaming](./streaming.mdx) for streamer behavior.

## Generate with images, video, or audio

Pass a matching language GGUF and projector GGUF to `VLMPipeline` on CPU. This route uses the
OpenVINO GGUF frontend and reuses the image processing, embedding assembly, and generation code
used for Optimum Intel exports.

```python
import numpy as np
from PIL import Image
import openvino as ov
import openvino_genai as genai

pipe = genai.VLMPipeline(
    "model.gguf", "CPU", mmproj_path="mmproj.gguf"
)
image = ov.Tensor(np.asarray(Image.open("image.jpg").convert("RGB"))[None])
print(pipe.generate("Describe the image.", images=[image], max_new_tokens=64))
```

In C++, pass `ov::genai::mmproj_path("mmproj.gguf")` to the `VLMPipeline` constructor.
The existing image, video, audio, and chat APIs apply.

| Language architecture | Matching projector | Media |
| --- | --- | --- |
| Gemma3 | `gemma3` | Images |
| Gemma4 | `gemma4v` or `gemma4uv` | Images, video; audio when present in the projector |
| Qwen3.5 / Qwen3.5 MoE | `qwen3vl_merger` | Images, video |
| Muse Glimmer | `muse-glimmer` | Images, video |
| LLaVA 1.5 | `mlp` | Images |
| InternVL | `internvl` | Images |
| LFM3-VL | `lfm3vl` | Images, video; requires the frontend LFM3 support |

LLaVA 1.5 and InternVL use the existing native frontend vision graphs. LLaVA Next and
MiniCPM-V are not included in these additional projector routes. For a LLaVA checkpoint without
a chat template, provide its formatted prompt and set `apply_chat_template=False` when generating.

Other language/projector pairs are rejected.
The supported pairs still depend on the OpenVINO frontend version. Paged attention is selected
using the existing backend rules; request `ATTENTION_BACKEND="SDPA"` explicitly when needed.

## Load models with extensions

Pass `extensions` to the pipeline constructor to load GGUF frontend extensions. `LLMPipeline`
and `ContinuousBatchingPipeline` require `GGUF_READER="FRONTEND"`; `VLMPipeline` registers the
same extensions on its language and projector frontends. See [Extensions](./extensions.mdx#use-extensions-with-the-gguf-frontend)
for Python and C++ examples and the supported extension types.
